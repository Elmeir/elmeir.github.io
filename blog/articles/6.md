异步的难处不在语法，而在「什么时候轮到谁」。食堂最能讲清这件事。

## 一口大锅与一条小灶

把事件循环想成食堂：宏任务是**大锅菜**窗口，setTimeout 与 I/O 都在那一列排着；微任务是**小灶**窗口，Promise.then 与 queueMicrotask 随到随炒。规矩只有一条：**大锅每出一轮菜，小灶必须清空一轮**，这一轮才算结束。

## 所以谁先执行

```js
setTimeout(() => console.log("大锅"), 0);
queueMicrotask(() => console.log("小灶"));
console.log("端菜");

// 输出顺序：端菜 → 小灶 → 大锅
```

`setTimeout(fn, 0)` 的 0 不是「立刻」，是「下一轮大锅」；而微任务在本轮收尾就要清空。所以它不一定比 `queueMicrotask` 后执行——准确说，是**一定**在其后。

## async/await 只是糖衣

`await` 之后的代码，本质是被塞进了微任务队列。`async` 函数遇到第一个 `await` 就先端着盘子离队，回来时再排小灶——语法再甜，队伍的规矩不变。

## 吟唱顺序心法

同步代码最先唱完；微任务插在每轮宏任务的间隙里合唱；宏任务按队伍慢慢来。记住这句，食堂里的时序之争，九成都能靠嘴算破案。

> 语法只是糖衣，队伍的规矩从来没变过。
