魔导书的每一叶都有正反两面。麻烦在于，浏览器并不总能判断哪一面朝着你——而它一旦判断错，也不报错，只是让纸变得透明。

## 第一条：别给纸刷清漆

给面加 `filter`（哪怕只是 `saturate(.9)` 做质感）或小于 1 的 `opacity`，浏览器会把这一面**拍平成独立合成层并跳过背面剔除**——翻过 90° 之后，正面透过背面继续画出来，叠成一片镜像的字。

要调明暗的正解不是滤镜，是在本体之上**叠一层只改 background-color 的伪元素**：

```css
.rb-face::after{
  background:rgba(0,0,0,0);
  transition:background-color .3s;
}
```

需要变暗时只改这一层的底色。它既不是分组属性，也不参与 3D 剔除，观感与滤镜等价。至于立体质感，一律交给渐变本身的明暗去表达。

诚实交代一句：**这条 bug 我在本项目里从未复现过。** 用 `?freeze=-135` 把封面冻结在越过 90° 的姿态做命中测试，有 filter 与无 filter 两种情况，命中的都不是封面那层皮——背面剔除均正常。无头 Chromium 是强制合成模式，与真实 GPU 渲染可能有差异。规则照旧（规范优先、改动零成本），但哪天真收到「开书瞬间封面闪一下」的反馈，别忘了无头测不出这一层。

## 第二条：面要自己先转一次

Firefox 下，若背面朝向完全来自**祖先的旋转**、自身没有任何 transform，它就不做剔除——正反两面共面叠印，纸面上会出现贯穿布面的竖向接缝和镜像的字。

解法是给双面结构的每个面都写上显式 `transform: rotateY(0deg)`：零旋转也算变换，Firefox 才会把祖先的旋转计入累计矩阵。Chrome 无此要求，写了无害——跨浏览器的配方保持一致，比记住哪条属于哪个引擎便宜得多。

## 第三条：被剔除的那面，阴影会漏出来

`backface-visibility: hidden` 剔除的是面的**内容**，面的 `box-shadow` 照画不误。翻页后半程，已剔除面的阴影就透到下层页面上，成了一个半透明的轮廓。

解法是把装饰（背景 + 阴影）全部下沉到内层 `::before`，面本体零装饰：子树随面整体剔除，阴影便无从单独泄漏。

## 第四条：overflow 是清白的

`overflow: hidden` **不属**分组拍平，可以放心用它裁剪内层越界的阴影。

这一条是排除项。上面三条都在收缩可能性，这一条负责把还剩下的那扇门指给你——**知道什么不必怕，和知道什么必须怕同样重要。**

> 背面剔除只剔除内容：清漆、阴影、滤镜，都会从纸的背面漏出来。
