这本书的每一页都印着横线，行距锁死一格。于是任何一个偷偷长高的行盒，都会让它**后面所有**的字一起漂出格线——罪证离现场最远。

## 行盒是并集，不是一个数

行盒的高度，是块内所有 inline box（含 strut）按基线对齐之后取**并集**；而单个 inline box 的半行距 = `(line-height − 字身) / 2`。

推论有点反直觉：**凡是 `font-size` 比父级小的行内元素**（`code`、`kbd`、小号上标），字身更小，半行距反而更大——它的下边缘探出汉字 strut 的下边缘，整行被顶高。

实测里，正文块的高度冒出 61 / 92 / 122 / 183px（2.03 / 3.07 / 4.07 / 6.10 格），一篇之内从 +1 一路漂到 −13。

## 压住行内代码的 line-height

```css
.art-page code{ line-height:1; }
.art-page pre code{ line-height:inherit; }
```

取 1（等于自身字号）时，代码的上下缘缩进 strut 之内，行盒重新由 strut 说了算，精确落回周期，**看上去毫无变化**——背景色块画的是字身，与 line-height 无关。

代码块必须豁免：`pre` 的正文整个裹在 `<code>` 里、还跨了多行，那里的 code 就是行本身的生产者，一豁免，每行就只剩 .92em。

**判据只与字体的 (ascent − descent) / em 比例有关，与 font-size 无关**——所以把代码字号调回 1em 治不好（实测仍撑 0.8px），只能压 line-height。上界藏在字体度量里、算不准，**别套公式，拿工具实测**：好工具会直接指给你看，是哪一行的哪一个字在撑。

## 同一条规矩，两副面孔

同一条机制，换一双眼睛就是两副面孔：一位量到 90 / 150 / 60，分毫不差；另一位量到 91.5 / 152.5 / 61，每行多出 0.5。

所以「某某精确 30px」从来不是定律，只是它没踩中你踩的那个点。把 `pre code` 的字号一并拉平之后，半行距与 strut 对齐，与字体度量彻底脱钩——这才是根治，不是调参。

## 滚动条也占半格

`pre` 里的内容一旦超宽，块底就会长出一条 **15px** 的横向滚动条，块高凭空多半格（75 = 60 + 15），其后的正文整片掉出格线。不超宽的 `pre` 恰好 90 / 150 整格。

一眼看穿的办法是看**盒差**（`offsetHeight − clientHeight`）：不是零，就说明块高里混进了边框或滚动条。修法是让滚动条不占布局高度，横向照样能滚：

```css
.art-page pre{ scrollbar-width:none; }
.art-page pre::-webkit-scrollbar{ height:0; }
```

两条都写：一条给标准那一派，一条给带前缀的那一派。

> 稿纸的横线是一条契约：行盒里任何一个偷偷长高的字符，都会让整页为它让路。
