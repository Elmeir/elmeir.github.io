CSS 的「不听话」几乎都能归到三件事上：**层叠**，也就是谁说了算；**继承**，也就是谁传给了谁；**优先级**，凭什么听你的。把这三件事的账算清，九成灵异事件都会现出原形。

## 优先级的算术

特异性按位记账，位高的赢；位相同时，后写的赢：

```css
#nav .item   /* 1-1-0 */
.list .item  /* 0-2-0 */
.item        /* 0-1-0 */
```

这就是为什么「明明写了却没生效」——多半是别处一个 ID，把你十节课的努力整个压死。

## :where() 的零特异性陷阱

`:where()` 里的选择器**不计入特异性**，本意是写「可被轻易覆盖的默认值」：

```css
:where(.btn) { color: #333; }   /* 0-0-0，谁都能覆盖 */
.btn { color: blue; }           /* 想覆盖，一行即可 */
```

陷阱在于：若这份默认值写在加载更晚的文件里，它同样谁也压不过——**零特异性是双刃剑，砍别人的同时也砍自己**。行内样式与 `!important` 则是两把重锤，能用一次，别造第二把。

## 继承：沉默的大多数

大多数字体类属性会沿着文档树悄悄下传，盒模型类属性则不会。子元素上「凭空出现」的样式，多半是祖辈的遗产；查清继承链，比对着选择器干瞪眼快得多。

## 朴素的真理

调试完这一轮，我的结论朴素得像句口头禅：**能生效的样式，才是好样式**。与其追求优雅的选择器，不如让每一行规则都清楚自己凭什么生效。

> 样式不听话时，先别急着改它——先回答三个问题：谁说了算、谁传给了谁、凭什么。
